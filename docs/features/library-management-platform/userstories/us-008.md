# US-008: Kiểm tra file nhập liệu bằng dry-run trước khi ghi

## User Story

Với vai trò **Quản trị viên**, tôi muốn chạy dry-run và nhận báo cáo lỗi theo từng dòng trước khi commit, để tôi sửa dữ liệu nguồn mà chưa làm bẩn kho chính thức.

## Context

Dry-run không được ghi dữ liệu chính thức và phải báo lỗi/trùng theo dòng. File Excel đại diện và mapping là external blocker.

**Trong phạm vi:** outcome nghiệp vụ nêu trên cùng validation, authorization, audit và recovery đã có nguồn trong SRS/UC.

**Ngoài phạm vi:** mọi ngưỡng, policy hoặc capability đang mang nhãn PROPOSAL/Open chưa được tự chốt trong story này.

## Acceptance Criteria

### AC-001 — Dry-run báo lỗi theo dòng và không ghi kho

* **Type:** happy-path
* **Covers:** FR-LMP-022 / BR-LMP-014
* **Screen:** `import-upload`, `import-report`

```gherkin
Given Quản trị viên nộp một file nhập liệu đọc được
When hệ thống chạy dry-run
Then báo cáo nêu tổng dòng, dòng hợp lệ, dòng lỗi kèm lý do, dòng trùng và dòng bỏ qua, và kho chính thức không đổi
```

### AC-002 — File không hợp lệ không tạo dữ liệu nghiệp vụ

* **Type:** error-path
* **Covers:** FR-LMP-022
* **Screen:** `import-upload`, `import-report`
* **Error code:** E-LMP-014

```gherkin
Given file nhập liệu sai định dạng hoặc không đọc được
When Quản trị viên yêu cầu dry-run
Then hệ thống không ghi dữ liệu nghiệp vụ và báo file không hợp lệ
```

> **BLOCKING DoR:** OQ-LMP-002 phải cung cấp file Excel đại diện và mapping. Chưa có AC cho từng cột hay quy tắc trùng cụ thể.

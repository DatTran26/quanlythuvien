Mỗi ảnh ≤500KB sau nén (NFR-05); kiểm tra loại/MIME sniffing, quét nội dung, tên file an toàn, không tin metadata gốc (BR-damage-lifecycle-002, FR-damage-lifecycle-002).

Submit → 1 transaction: DamageReport PENDING + Copy →PENDING_REVIEW + audit + outbox notify Thủ thư. Chặn lưu thông ngay khi báo hư hỏng là mặc định — Open, chưa chốt (OQ-11).

Báo phát hiện trong luồng trả: hệ thống đóng Loan + assess phạt BR-07 TRƯỚC rồi mới tạo report (COPY-T05 — FACT), gắn loan_id vào report.

Trạng thái lỗi
E-core-001 — Thiếu mức độ/ghi chú/ảnh: inline error, giữ dữ liệu nhập, cho sửa và submit lại; không tạo report.
E-core-003 — Mã không trỏ Copy hợp lệ → error panel cho nhập lại; Copy đã có report PENDING → hiển thị report hiện có (gộp/từ chối idempotent — PROPOSAL).
E-damage-lifecycle-001 — Upload bị từ chối (sai loại/vượt 500KB/nội dung rủi ro): attachment error, cho chọn file khác — không lưu file rủi ro; quá 5 ảnh → từ chối phần vượt.
E-core-008 — Copy ở trạng thái terminal (DISPOSED) hoặc không hợp lệ báo cáo: từ chối, reload trạng thái.

Disposition — Thủ thư (chỉ khi PENDING)

Disposition tối thiểu R1A theo DEC-P2-03 (FACT nguồn FR-L08). Report chỉ đóng khi có quyết định + audit đầy đủ (BR-damage-lifecycle-001); ghi cùng transaction + outbox notify.

Xác thực lại — E-access-control-001 (step-up)
Thanh lý là tác vụ nhạy cảm (DEC-D3-07): yêu cầu xác thực lại + lý do trước khi ghi; điều hướng tới màn [5] Phiên hết hạn / step-up của auth-flow (màn chung). Fine DAMAGE gắn Loan (nếu có) giữ độc lập — không bị xóa theo.
Khi Copy đang IN_REPAIR

Queue rỗng → Copy IN_REPAIR→AVAILABLE (COPY-T12); có hàng chờ → IN_REPAIR→ON_HOLD + Reservation đầu queue READY + hold_expires_at (baseline đề xuất 48h — PROPOSAL, OQ-policy-config-001/OQ-04) + notify (COPY-T13, áp dụng từ R2). Sửa không thành → bổ sung disposition DISPOSE hoặc report mới (PROPOSAL — DEC-D3-07).

Tác vụ khác

E-core-008: report đã terminal (REJECTED/REPAIR/DISPOSE) → từ chối action, reload state, chỉ hiện action hợp lệ; report không reopen.
